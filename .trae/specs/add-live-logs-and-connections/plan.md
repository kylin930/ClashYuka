# 实时日志与连接规划

## 目标与范围

用户可以在现有日志页观察 Mihomo 的实时输出，在连接页找到当前连接、查看路由详情并关闭指定连接。沿用现有页面和内核会话；本轮不做持久化、导出、历史连接及全部关闭。

## 行为

- **日志**：内核就绪后接收实时日志；移除示例数据。保留等级筛选、搜索、自动滚动和清空。清空只影响本地记录，不中断接收。仅在内存保留最近 500 条，限制单条长度和待处理数据，批量发布；退出后不留历史。对已知的控制器密钥和订阅地址做脱敏，不将原始日志转写到应用诊断日志。内核停机后允许查看本次记录，开启下一会话时清空。
- **连接**：页面显示最新活动连接，支持按端点、规则或代理链搜索及 TCP/UDP 筛选。列表显示目标、协议、代理链和流量；详情补充来源、规则等已提供的数据。选择按 ID 保持；连接消失则清除详情。区分内核未运行、等待数据、连接流中断、无活动连接和无筛选结果。
- **关闭单条**：从选中连接发起并确认。仅对当前会话中存在的 ID 执行，在后台请求，等待后续连接快照更新列表；重复请求、旧会话结果不得影响新会话。失败提示不包含原始响应正文。关闭不是阻止后续重连。
- **生命周期**：复用现有本地控制器连接；停机或切换会话后不再接纳旧数据。流中断不停止内核，恢复后的数据能重新刷新页面。退出不保留后台任务。

## 实施顺序

1. 接通内核日志和完整连接快照，加入单条关闭 API，覆盖解析、会话隔离及请求路径测试。
2. 接通应用状态与原生页面，验证缓存上限、过滤、空态、选择和关闭反馈。保留现有系统代理改动。
3. 使用 VS CMake 预设编译并跑 CTest；可用时用隔离目录、回环端口及本机 Mihomo 验证。不开系统代理，不使用桌面自动化或私人订阅。

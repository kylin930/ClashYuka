# 配置与订阅规范

## 为什么

Profiles 页目前只展示占位条目，用户无法在应用内导入日常使用的 Mihomo 配置。此阶段补齐从导入、刷新到启用与恢复的流程，不扩展到 TUN 或完整配置编辑器。

## 变更范围

- 支持导入本地 Mihomo YAML，以及通过 HTTPS 添加返回完整 Mihomo YAML 的订阅。
- 提供配置列表、重命名、删除、启用、手动刷新及可选定时刷新。
- 区分「下次启动配置」和「当前运行配置」，并保留可随时选择的内置配置。
- Windows x64 为首要验收平台；没有 HTTPS 后端的平台明确禁用远程入口，本地配置仍可用。不新增 UI 框架，不改动既有系统代理方案。
- 本轮不做裸节点订阅转换、脚本或配置覆写链、YAML 编辑器、TUN、后台服务和跨设备同步。

## 影响

- 能力：配置管理、远程订阅、内核启动选择、失败恢复与状态展示。
- 模块：Profiles、Dashboard、AppState/AppController、RuntimeConfig/KernelSession、HTTPS 平台层和测试。现有系统代理工作区改动须保留。

## 新增要求

### 要求：添加并管理配置

Profiles 页须展示内置、本地和订阅配置，标明类型、名称、选中状态，以及适用的最近刷新状态。内置配置不可删除。导入成功只入库，不自动启用；源文件不修改，后续启动不依赖源文件仍存在。配置库与订阅信息保存在用户数据目录，沿用现有工作目录和手工运行配置时不得覆盖用户文件。

#### 场景：导入或删除
- **当** 用户选择通过校验的本地 YAML 时，**则** 导入独立副本并提示成功；取消选择、文件不可读或格式不支持时，配置库不变。
- **当** 用户删除普通配置时，**则** 先确认；正在使用或被选为下次启动的配置须先切换，不能直接删除。重名不应覆盖原条目。

### 要求：校验与隔离

仅接受大小受限、可解析且根为映射的 YAML。导入与刷新均校验；不能把语法检查标为已通过 Mihomo 验证。有可用内核时，启用前用现有进程抽象运行有界的 Mihomo 配置检查，检查失败不替换正在运行的配置。没有内核时允许保存和选择，首次启动前再执行内核检查。首次覆盖范围为自包含配置及不依赖外部本地文件的远程 provider；依赖外部本地文件的配置明确报不支持。

应用生成独立运行副本：应用管理的 API 地址、Secret、mixed-port 与回环监听以应用设置为准；不接收配置提供的其他控制器入口，不允许配置扩大监听范围或开启 TUN。保留支持的代理、组、规则等内容；无法安全生成运行副本时拒绝启用，并说明原因。

### 要求：订阅刷新

订阅只接受 HTTPS，校验证书，不允许重定向降级到 HTTP。下载在后台执行，具有限时、限量和取消；网络、HTTP、取消及内容校验错误可区分。沿用系统代理或应用下载代理的选择，不影响 Mihomo 本地 API。订阅 URL 可能含令牌，只在编辑时按需显示，不进入日志或普通错误消息；本地保存不是加密保险库。

#### 场景：刷新成功或失败
- **当** 用户手动刷新，或开启定时刷新后在应用打开期间到期，**则** 下载并校验新内容，成功才原子更新本地副本；默认不启用定时刷新，同一订阅只允许一个刷新任务。
- **当** 下载、校验或写入失败，或用户取消时，**则** 保留上次有效数据与运行状态。刷新当前配置只提示有新副本，不自动重启；用户可显式应用。关闭应用应取消后台任务，不发布迟到结果。

## 修改要求

### 要求：配置选择与启动

内核关闭时，选择配置只保存下次启动选项。内核运行时，切换或应用新副本须经确认，再走现有 KernelSession 的串行生命周期；只有新内核通过 API readiness 后，才显示为当前运行配置并提交切换。拒绝或取消确认不改变运行状态。

#### 场景：启用失败
- **当** 预检查失败，**则** 不停止旧内核。
- **当** 新配置在切换后启动失败，**则** 尝试用旧配置的准确运行副本恢复；不将失败配置标为运行中。旧内核也未恢复时，应明确显示失败，并保留旧配置和内置配置入口供手动恢复。
- **当** 原选中配置在应用启动时遗失或不可读，**则** 提示用户并提供内置配置入口；不静默覆盖原选择、不擅自启动其他配置。正常退出和切换期间维持系统代理原有的恢复行为。

# Windows 系统代理可靠性规范

## 为什么

ClashYuka 已有 Windows 当前用户固定代理开关，能在内核就绪后启用，并在正常停止和退出时尝试恢复。当前备份只保存在进程内，异常退出后无法恢复，且恢复时可能覆盖用户或其他应用后来修改的代理设置。本轮完善现有开关，不另建代理管理入口。

## 变更范围

- 完善 Windows 当前用户固定 HTTP/HTTPS 系统代理的开启、恢复、冲突处理和状态反馈；保持默认关闭和原有配置兼容。
- 复用现有设置页、内核生命周期和配置切换流程。无 Windows 后端的平台维持不支持，不写系统设置。
- 不新增 PAC 服务、WPAD 管理、持续抢占式代理守护、TUN、管理员服务或 WinHTTP 全局代理设置；已有 PAC 设置纳入恢复范围。

## 修改要求

### 启用与停用

用户开启开关只表示启用意愿。仅当本次内核会话 API 就绪、有效的回环 mixed-port 已知，且原代理状态可完整读取并保存时，才接管系统代理。不可用时显示等待或失败，不显示已接管。代理接管后，开关关闭、内核停止或异常退出以及应用正常退出均须尝试恢复接管前的设置。配置切换或回退时只对当前已就绪会话生效，旧会话结果不能重新接管。关闭开关不停止内核。

接管前保留原有固定代理、绕过列表和 PAC 的值及存在状态；恢复不等同于关闭代理。应用应确认写入和恢复结果，部分写入失败时尝试撤销自身改动；写入或恢复失败须可见，不得清除尚有用的恢复信息。

### 异常退出与外部冲突

首次修改系统前须保存可跨应用重启的恢复记录，并能识别应用实际写入的状态。下次启动先检查遗留状态，再决定是否按已保存的开关偏好接管。若系统仍保留应用留下的设置，恢复原状态；若已恢复则清理记录，不重复写入。恢复失败显示原因和重试入口，不继续自动接管。

若用户或其他进程改动了代理，应用不得把外部改动覆盖回自身值，也不得盲目覆盖整个原快照。能确认仍由应用留下的值才允许恢复；无法判定时保留现状，明确提示冲突与处理入口。并行应用实例不能相互接管或绕过待处理恢复记录。企业策略或权限阻止修改时，报告未接管，不尝试提权或绕过策略。

### 状态反馈

设置页区分关闭、等待内核、已接管、待恢复和冲突或失败；重试只在有可重试操作时可用。显示应用自己的回环地址即可；原代理和 PAC 地址不进入普通错误或日志。恢复记录留在本机，不同步也不上传。

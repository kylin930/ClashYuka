# Visual Studio MCP 使用规范

当前项目 ClashYuka 使用 C++20 + CMake + wxWidgets。

Visual Studio 通过 Open Folder / CMake Folder Mode 打开项目。

## 核心原则

1. CMake 是唯一权威构建系统。
2. 不要求生成 .sln、.slnx 或 .vcxproj。
3. 不将 NoSolution 判断为项目配置错误。
4. 优先使用 Visual Studio MCP 检查 IDE、编辑器、诊断和调试状态。
5. 使用 CMake Presets 管理构建配置。
6. 使用 CMake 和 Ninja/Visual Studio Generator 完成实际构建。
7. 使用 CTest 管理测试。

## MCP 工具使用要求

不要只在连接测试时调用 get_status。

根据任务主动选择对应工具：

- get_status：检查 VS 环境。
- get_help：确认当前可用工具。
- file_read：读取代码。
- file_open：在 VS 中打开文件。
- file_edit：精确修改文件。
- find_in_files：搜索代码。
- code_goto_definition：查看定义。
- code_find_references：检查引用关系。
- output_read：读取 VS 输出。
- error_list_get：读取错误列表。
- test_discover：发现 C++ 测试。
- test_run：执行测试。
- ui_snapshot：检查 GUI。
- ui_capture_window：截取程序窗口。
- debug_start / debug_attach：启动或附加调试。
- debug_get_callstack：排查调用栈。
- debug_get_locals：查看变量。
- breakpoint_set：设置断点。

## 构建规范

对于 CMake 工程：

- 不使用 build_solution 代替 CMake 构建。
- 不使用 build_project 代替 CMake 构建。
- 通过 CMake Presets 配置。
- 通过 cmake --build 构建。
- 通过 CTest 执行测试。

如果 VS MCP 的调试工具不支持当前 CMake 启动目标，使用可用的 CMake 调试配置或进程附加方式，不要创建传统 VS 工程来绕过。

## GUI 验证

ClashYuka 是 wxWidgets 原生桌面程序。

开发 GUI 时：
1. 使用 ui_capture_window 获取实际程序截图。
2. 使用 ui_snapshot 检查可访问的 UI 元素。
3. 使用 UI 自动化完成适用的交互测试。
4. 对自绘控件，不假定其一定暴露完整的 UI Automation 元素树。
5. 每次主要 UI 修改后进行实际运行验证。

## 安全要求

- 编辑前检查工作区状态。
- 不擅自覆盖用户修改。
- 重要修改前确保 Git 有可恢复的提交。
- 调试和构建时保留完整错误日志。
- 不要仅凭代码检查就宣称功能测试通过。
